# 実装前段階プラン — GLB 内テクスチャのアップロード段階でのスケール変更

[索引に戻る](README.md)

## 目的

- サーバ保存前に解像度を上限化し、**転送量と GPU メモリ**を抑える。

## スコープ

| 含める | 含めない（初期） |
|--------|------------------|
| アップロードパイプラインでの再エンコード（例: glTF-Transform `resize`） | クライアント側だけでの canvas リサイズのみに依存する方針 |
| 上限ピクセル数・フォーマット方針の文書化 | KTX2 / Basis 全自動パイプライン（別プロジェクト化しやすい） |

## 調査・決定タスク（実装前）

1. **実行場所**: `server.js` 内同期処理か、ワーカー／キューか（大ファイル・タイムアウト）。
2. **上限値**: 色テクスチャ / 法線の別上限、最大ファイルサイズとの関係。
3. **透過・alpha**: リサイズ後の品質と glTF マテリアル互換。
4. **Draco / メッシュ**: テクスチャ縮小と Draco の順序（既存 `DRACOLoader` 利用者への影響）。

## 参考（技術調査用）

- [@gltf-transform/cli](https://www.npmjs.com/package/@gltf-transform/cli) の `resize`、公式ドキュメント [gltf-transform.dev](https://gltf-transform.dev/)。

## 実装計画フェーズに渡す成果物

- 採用 CLI またはライブラリ API の確定、**失敗時のレスポンス**（元ファイル拒否か、そのまま保存か）のポリシー。
