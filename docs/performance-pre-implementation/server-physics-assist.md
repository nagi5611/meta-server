# 実装前段階プラン — 物理演算のサーバ側補助（床貫通時ロールバック等）

[索引に戻る](README.md)

## 目的

- クライアント物理の破綻やチートに対し、**サーバが許容範囲を検証**し、異常時は正当な位置へ戻す（軽量なら Z クランプ、重いらば権威物理）。

## スコープ（段階案）

| 段階 A（小） | 段階 B（大） |
|--------------|--------------|
| 最終的な Y（または床下検出）のサーバ検証とロールバック | サーバ上で Rapier 等の剛体シミュとクライアント同期 |

## 調査・決定タスク（実装前）

1. **真実の地形データ**: サーバが **どの幾何**を持つか（簡略コライダ、高さ場、チャンク単位メッシュ）。現状メッシュはクライアントのみの可能性が高い。
2. **同期モデル**: 位置はサーバ権威か、客寄せ＋補正か。`player-update` の頻度・レイテンシとの整合。
3. **ロールバックの UX**: 瞬間移動か、滑らかに補正するか。VR だと酔いのリスク。
4. **段階 A で足りるか**: 「床下なら直前フレームへ」だけで要件を満たせるか。

## リスク

- サーバが地形を知らないままでは **検証不能**。チャンク・コライダ配信とセットで工数が跳ねる。

## 実装計画フェーズに渡す成果物

- 採用する段階（A or B）の決定、サーバが参照する **地形データ仕様**のたたき台（ファイル形式・更新タイミング）。
