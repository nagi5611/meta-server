# 実装前段階プラン — チャンクローディング（範囲外は skybox のみ・非描画）

[索引に戻る](README.md)

## 目的

- 視界・距離外のジオメトリを **シーンに載せない or visible=false** にし、ドローコールと三角数を抑える。遠景は skybox / フォグで誤魔化す。

## スコープ

| 含める | 含めない（初期） |
|--------|------------------|
| チャンク境界・ロード単位の定義 | OGC 3D Tiles への全面移行 |
| プレイヤー位置に応じたロード・アンロード | 無限 procedual ワールド生成 |

## 調査・決定タスク（実装前）

1. **データ分割**: 現状の「1 ワールド = 複数モデルエントリ」でチャンク相当にできるか、**地理的チャンク用の新スキーマ**が必要か。
2. **座標系**: チャンク原点、ワールド原点、モデル個別 `position` の関係を文書化。
3. **アンロード**: `dispose()`（geometry/material/texture）の責務とメモリリーク防止の方針。
4. **同期**: 他プレイヤーが遠くのチャンクにいる場合の表示（常に全ロードはチャンクの意味が薄れる）。

## 参考（技術調査用・採用は未決）

- 空間分割・タイル系: three.js `Octree`（addons）、コミュニティのタイルローダ等。任意配置 GLB ワールドとの相性は要検証。

## リスク

- コンテンツが「巨大単一 GLB」のままでは **分割なしでは効果が出ない**。配信・編集フローの変更がボトルネック。

## 実装計画フェーズに渡す成果物

- チャンクサイズ・ロード半径のたたき台数値と、**ワールド定義の拡張案**（後方互換をどう保つか含む）。
